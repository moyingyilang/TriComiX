## 四、怎么测

```bash
# 自检：不联网、不需要账号，12 项端到端纯逻辑检查
probe.sh eh "" 1 selfcheck

# 只打印将要访问的地址，不联网
probe.sh eh "关键词" 1 dry

# EH 完整链路（当前环境会超时，需换网络）
probe.sh eh "关键词" 1 full

# Pica：登录后跑完整链路（密码走环境变量，避免进入进程列表）
TRICOMIX_PASS='你的密码' probe.sh pica "关键词" 1 full 你的邮箱

# 收藏
TRICOMIX_PASS='你的密码' probe.sh pica "" 1 fav 你的邮箱
```

探针会逐步打印并**指出失败发生在哪一环**，失败不会被伪装成空结果。

## 五、自检能覆盖什么

`probe.sh eh "" 1 selfcheck` 跑 12 项端到端纯逻辑检查，**已全部通过**：

| 自检项 | 它证明了什么 | 它不能证明什么 |
| --- | --- | --- |
| Pica 签名原文 5 段、不含 baseUrl/版本号 | 拼接顺序与"以原生层为准"的结论一致 | 服务端是否真按 5 段校验（已由 401 证据间接支持） |
| Pica 内置密钥 63 字节 | 字符串转义没写错 | 密钥是否长期有效 |
| Pica 签名 64 位小写十六进制 | 编码正确 | 无 |
| Pica 请求头齐备 + `authorization` 有无 | 头集合完整、登录前后行为正确 | 服务端是否还需要 `app-nonce` |
| Pica 端点构造 | 路径与参数拼写正确 | 端点是否存在（已由真实请求到达服务端间接支持） |
| Pica 缺 `code` 不默认成功 | 不会把失败当成功 | 无 |
| EH URL 构造 | 五个 URL 形状正确 | 站点是否仍用这些路径 |
| EH 列表解析 | 对给定形状自洽 | **真实页面是否这个形状** |
| EH 详情 `showkey` + 逐页 `imgkey` | 两个键的提取规则正确 | 真实页面是否仍这样写 |
| EH `showpage` + `hath` | 地址与 hath 提取正确 | 真实响应片段是否如此 |
| EH 登录解析（成功与失败） | 两种页面都能正确判定 | 真实登录是否成功 |
| EH cookie 快照往返 | 持久化能力可用 | 真实站点下发的 cookie 形态 |

**结论**：自检能挡住"重构把协议或选择器改坏"，但**每一条真实形状都必须由使用者在真实环境验证**。

## 六、单测覆盖

所有单测都用**我们自己写的合成样本**（HTML/JSON），真实结构来自对参照实现的静态阅读。
合成样本能证明"解析逻辑对给定形状是自洽的"，**不能证明"真实页面就是这个形状"** ——
后者只能由真实环境验证。

当前单测数：`source-pica` 33 项、`source-eh` 64 项，合计 **97 项**；另有自检 12 项。
